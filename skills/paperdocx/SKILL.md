# PaperDocx · Markdown 论文 → 投稿级 Word

**一句话：pandoc 负责把 md 的结构变成 Word 原生对象（OMML 公式、表、图），python-docx 负责套样式和接 Zotero。两边各干各擅长的，别互相代劳。**

这套东西是 2026-10-16 为一篇投 RSE 的遥感论文（17 000 词 / 23 图 / 12 表 / 14 公式 / 62 条文献）实做出来的，每条参数都是从两份真实的投稿稿里**读出来**的，不是编的。

---

## 什么时候用它

```
✓ 有一份 Markdown 的论文稿，要出投稿用的 Word
✓ 要三线表、公式带编号右对齐、参考文献接 Zotero
✓ 作者要在 Word 上改字，改完还要能回到 md（双向联动）
✓ 作者会在 Word 里调样式，但不希望下次重出被冲掉
✗ 只是把 md 转个 docx 看看 —— `pandoc a.md -o a.docx` 就够了
✗ 要排中文期刊的格式 —— 参数不一样，但这套框架能改（看「换一本刊物怎么改」）
```

## ★★ 一条命令走完（日常就用这个）

```powershell
py -3.12 -X utf8 排版/走一遍.py           # 配文献 → 排版源 → 出预览 → 渲染 → 三项验收
py -3.12 -X utf8 排版/走一遍.py --交付     # 版面没问题了，再出一版原图交付稿
```

实测（一篇 42 页 / 23 图 / 7 表 / 12 公式 / 65 条文献的稿子，2026-10-19）：

| 步骤 | 用时 |
|---|---|
| 配文献（65 条 ↔ 库里 998 条） | 8 s |
| 做排版源 | 1 s |
| 出 Word（`--图dpi 300` 预览版） | 20 s |
| 真 Word 导 PDF + 42 页转 PNG | 24 s |
| 结构体检 + 文献表逐条比 | 2 s |
| DOI 核实 65 条 | **0 s（后台，和出 Word 同时跑）** |
| **合计** | **55 s** |

同一件事第一次做花了一个多小时。省下来的**不是靠并行**，是靠这三条：
**① Zotero 库按版本号缓存**（库一改自动重拉，不靠人判断）、
**② 默认只出预览版**（原图版几十 MB，写盘和导 PDF 都慢，验收完再出一次）、
**③ 把联网的 DOI 核实扔后台**。
前三步是硬链（出 Word 要 `引用映射.tsv`），别为了并行拆它。

## 补充材料怎么出

和正文一样一条命令，只是换个源：

```powershell
py -3.12 -X utf8 排版/出Word.py --源 V49_补充材料.md --图dpi 300 --出 _预览_补充材料.docx
py -3.12 -X utf8 排版/出Word.py --源 V49_补充材料.md --出 V49_补充材料_排版版.docx
```

* 编号带 `S` 前缀（`**Table S1.**` / `**Figure S1.**` / 公式 `(S1)`）都认
* **没有参考文献表是正常的**（文献表在正文稿里）：没有占位块就不插文献表，
  正文里的引用照样变成 Zotero 活字段
* `验docx.py` 对补充材料不要求书目字段

> ★ 这两条 2026-10-19 之前都是**做不到**的：`认类型` 写的是 `[0-9A]+`，
> `Table S1.` 匹配不上，7 个图表题全被当成正文段；没有占位块则直接报错出不来。

## ★★ 第一步：参数从哪来 —— 读一份参考 docx，别凭印象填

```powershell
py -3.12 -X utf8 排版/探参考docx.py 参考稿.docx            # 全读
py -3.12 -X utf8 排版/探参考docx.py 参考稿.docx --只 表格   # 只看表
py -3.12 -X utf8 排版/探参考docx.py 参考稿.docx --配置      # 直接吐出配置片段
```

`排版配置.py` 里的每个数字 —— 页边距 2.30 cm、正文 11 pt、行距 1.5、表头上线 sz=12、
公式编号列 1.80 cm —— **都是这么读出来的**。

> ⛔ **不许凭印象填。** 「RSE 大概 12 pt 吧」这种猜法，出来的稿子一眼就不对。

### 换一本刊物的标准动作

```
① 找一份那本刊物的、排版好的稿子（自己或同事投过的最好）
② py -3.12 -X utf8 排版/探参考docx.py 它.docx --配置
③ 抄进 排版配置.py
④ 出一版，渲染成图，和参考稿并排看
```

### ★ 实战：2026-10-16 读了两份，各取一半

| 参考稿 | 学到什么 |
|---|---|
| 一份 RSE 投稿稿 | 页面、页边距、字号、标题层级、行距、段前段后、三线表线宽、公式双列表结构 |
| 一份 ISPRS 投稿稿 | ★ **表格每个单元格都居中** —— 作者说「前一份里图表的排版不好」就是这一条 |

RSE 那份的表**只有表头**居中，数据行是左/右对齐，读起来散；
ISPRS 那份**整表每格 `jc=center` + `vAlign=center`**，紧凑得多。

⇒ **参考稿不必只看一份，也不必全盘照抄。** 一份看整体版式，一份看局部（图表、公式），
把好的那一半挑出来。

### ★★ 读参考稿时最容易上当的一点：格式不在样式定义里

实测：那份 RSE 稿的 `Body Text` **样式定义**里 `size` 和 `line_spacing` 全是 `None`，
而真实段落的 run 是 **11 pt、行距 1.5**。

很多投稿稿（尤其 pandoc 生成再手改的）**格式落在 run 和段落上，不在样式定义里**。
只读 `doc.styles` 会得到一串 None，照抄出来完全不对。

⇒ `探参考docx.py --配置` 的做法是：**按样式名把真实段落分组，每组取众数**。

> ★ 判断粗体要看**全段是不是都粗**，不能只看第一个 run ——
> 正文里有「**Weighted velocity loss.** 后面接正文」这种黑体小标题开头的段，
> 只看首 run 会把整个正文样式判成粗体。

## ★★ 全部参数和出处

**所有参数在 `scripts/排版配置.py` 一个文件里。改排版只改它，别去 `出Word.py` 里找硬编码。**

### 页面

| 项 | 值 | 出处 |
|---|---|---|
| 纸张 | A4（21 × 29.7 cm） | 读 Elsevier 投稿稿实测 |
| 页边距 | 上下 2.50 cm，左右 2.30 cm | 同上。正文宽 **16.40 cm**，所有表宽和图宽都按它算 |
| 分栏 | 单栏 | 投稿稿都是单栏，排版是期刊的事 |
| 行号 | **不加** | 有的刊物要，有的不要。要加就在 sectPr 里塞 `w:lnNumType` |
| 页码 | 页脚居中，用 `PAGE` 域 | 域不是死文本，页数变了自己更新 |

### 字体字号（全部走 Word 样式，不做 run 级硬格式）

| 用在哪 | 样式名 | 字号 | 粗 | 对齐 | 行距 | 段前/段后 |
|---|---|---|---|---|---|---|
| 题名 | Title | 16 | 是 | 居中 | 1.15 | 0 / 10 |
| 作者 | Authors | 11 | 否 | 居中 | 1.30 | 0 / 4 |
| 单位 | Affiliation | 8.5 | 否 | 左 | 1.15 | 悬挂 0.55 cm |
| 通讯 | Correspondence | 8.5 | 否 | 左 | 1.15 | 6 / 16 |
| 一级标题 | Heading 2 | 13.5 | 是 | 左 | 1.15 | 18 / 8 |
| 二级标题 | Heading 3 | 11.5 | 是 | 左 | 1.15 | 13 / 5 |
| 三级标题 | Heading 4 | 11 | 是 | 左 | 1.15 | 10 / 3 |
| **正文** | Body Text | **11** | 否 | **两端对齐** | **1.5** | 0 / 6 |
| 图注 | Figure Caption | 9.5 | 否 | 两端 | 1.15 | 2 / 14 |
| 表题 | Table Caption | 9.5 | 否 | 两端 | 1.15 | 14 / 4 |
| 表注 | Table Note | 9.0 | 否 | 两端 | 1.15 | 3 / 14 |
| 表格正文 | Table Cell | 9.0 | 否 | **居中** | 1.0 | 1.5 / 1.5 |
| 表头 | Table Header | 9.0 | **是** | 居中 | 1.0 | 1.5 / 1.5 |
| 参考文献 | Bibliography | 10 | 否 | 两端 | 1.10 | 悬挂 0.60 cm |

**字体一律 Times New Roman**，而且 `w:ascii` / `w:hAnsi` / `w:eastAsia` / `w:cs` 四个都要设 ——
不设 eastAsia 的话 Word 会给 `× − ⁻² µ` 这些字符挑中文字体，一眼就能看出来。

> ★★ **最隐蔽的坑：主题字覆盖显式字体。**
> pandoc 生成的 `Heading` / `Title` 样式带 `asciiTheme="majorHAnsi"`，
> **主题字优先级高于显式字体名**。只设 `w:ascii="Times New Roman"` 是没用的，
> 渲染出来是「正文衬线、标题一水儿无衬线」。
> 必须**先删掉 `*Theme` 属性再设实名**，`docDefaults` 里那份也要一起删。

### 三线表

```
┌──────────────────────────  ← 表头上线  sz=12（1.5 pt）
│  表头（加粗、居中）
├──────────────────────────  ← 表头下线  sz=8 （1.0 pt）
│  数据行（居中、垂直居中）
│  ...
└──────────────────────────  ← 末行下线  sz=12（1.5 pt）
          其余边框全部 nil
```

* **每个单元格水平 + 垂直居中**（`w:jc=center` 走样式，`w:vAlign=center` 走 tcPr）
* 表头行加 `w:tblHeader`，跨页自动重复
* 每行加 `w:cantSplit`，一行不许劈成两页
* ≤15 行的表整张 `keepNext`，不在页底被劈开
* 表宽固定 `w:tblLayout=fixed` —— 不固定的话 Word 无视你算的列宽
* 表整体居中 `w:jc=center`
* 格内边距：上下 40 twips，左右 85 twips

> ★ **pandoc 会按 md 的 `--:` / `:-:` 在单元格段落上写直接的 `w:jc`，它压过样式里的居中。**
> 必须删掉段落上的 `w:pPr/w:jc`，让 `Table Cell` 样式说了算 —— 这样作者以后改对齐，
> 改一次样式就全表生效。

### 列宽怎么算（放不下的时候怎么办）

```
① 按内容估每列的「下限」（最长单词）和「意愿宽」（最长串，上限 20 em）
② 缩放到正好铺满 16.40 cm，谁都不许低于下限
③ 放不下 → ★ 先收格内左右边距（85 → 60 → 40 twips），再缩字号（9 → 8.5 → 8 → 7.5 → 7）
```

> ★★ **顺序反了的代价实测过**：先缩字号的话，12 张表有 5 张掉到 7–8.5 pt；
> 换成先收边距，11 张留在 9 pt，只有 11 列的那张降到 8 pt。
>
> ★ **估字宽别一律按 0.5 em。** 按 0.5 估时表头 `LAI` / `NDVI` 被 Word 拆成
> `LA↵I` / `ND↵VI` —— Times New Roman 里大写字母是 0.70 em。分档：
> `ilj.,;:'!|()[]` 0.30 ／ 空格 0.25 ／ 数字 0.50 ／ 小写 0.48 ／ **大写 0.70** ／ `mwMW—–` 0.90。

### 公式：1×2 隐藏边框表

```
┌─────────────────────────────────┬──────────┐
│   （公式，OMML，水平+垂直居中）      │   (n)    │   ← 两格都居中
└─────────────────────────────────┴──────────┘
        14.60 cm                     1.80 cm
        tblBorders 六条全 nil，tblCellMar 左右 0
```

* 公式列宽 = 正文宽 − 编号列宽
* **OMML 自己也要居中**：往 `m:oMathPara/m:oMathParaPr` 里塞 `m:jc=center`，
  光设段落居中不够
* 表格里的行内公式要显式给 `m:r` 设 `w:sz`——**OMML 不吃段落样式**，
  不设的话在 8 pt 的表里按正文 11 pt 画，一眼大一圈

### 图

* 等比缩放到 ≤16 cm 宽 / ≤19.5 cm 高
* 图片段加 `keepNext`，图和图注不分家
* 图注用 `Figure Caption` 样式，`**Figure 1.**` 加粗、正文不加粗

> ★★ **Word 导 PDF 慢是图的体量，不是文档坏了。** 实测（同机、同稿、清干净 Word）：
>
> | 送进 docx 的图 | docx | Word 导 PDF |
> |---|---|---|
> | 原图 4251 px（675 dpi） | 59 MB | **30 分钟没出来** |
> | 400 dpi | 33 MB | 超 15 分钟没出来 |
> | **300 dpi** | **21 MB** | **12 秒** |
> | 200 dpi | 11 MB | 12 秒 |
>
> **不是线性变慢，21 MB 和 33 MB 之间有断崖。**
> 只影响导 PDF / 打印，**打开（8 秒）、改字、滚动、同步都不受影响**。
> 交付稿要原图就用原图，验收版面时出个 `--图dpi 300` 的预览版，版面一模一样。

### 参考文献：Zotero 活引用

正文里的引用是**真的 Zotero 复杂字段**（`ADDIN ZOTERO_ITEM CSL_CITATION`），不是死文本；
参考文献表是 Zotero 书目字段。作者在 Word 里点 Refresh 就能重排、换样式。

需要三样东西（见 `references/zotero接法.md`）：

```
references.json        CSL-JSON，id 换成 ref1..refN
zot_match_index.json   {refN: {itemKey, itemID, uri}}  ← Refresh 靠 uri 命中，不弹选择框
引用映射.tsv            refN ↔ 正文里**实际写的**渲染形式
xxx.csl                引用样式
```

### ★ 这四样不用手动做 —— `配文献.py` 自动配

```powershell
py -3.12 -X utf8 排版/配文献.py        # 先只看报告
py -3.12 -X utf8 排版/配文献.py --写    # 确认无误再写
```

它拿稿子 `## References` 里的纯文本条目，按**题名 + 第一作者姓 + 年份**去
Zotero 本地 API 配，配上了就吐出上面四个文件，配不上的写进 `引用数据/未命中.md`
（拿去 LitDoc 下载入库）。2026-10-18 实测：一篇 65 条的稿子，65 条全配上，
零歧义，比手动「导出 CSL JSON + 按题名回查 itemID」快得多。

**要 Zotero 开着**（本地 API 在 `127.0.0.1:23119`）。

**不出 DOI** 的做法：把 CSL 的 `access` 宏掏空就行，**Zotero 库里的 DOI 一个都不用删**。

```xml
<macro name="access"><text value=""/></macro>
```

> ★ 改完的 CSL 要**装进 Zotero 的 `styles/` 目录**（`<数据目录>/styles/`），
> 并且 **`<id>` 和 `rel="self"` 的 href 必须一致**，不一致 Zotero 拒装。
> **装完要重启 Zotero 才认得。**
> 不装的话：docx 里预渲染的文献表是没 DOI 的，但作者一点 Refresh，
> Zotero 会按它自己装着的原样式重排，DOI 全回来了。

> ★ **引用的显示文本直接用你自己的渲染表，别现编。**
> 重名作者（`Liu, C.` / `Liu, X.`）靠 CSL 的 `disambiguate-add-givenname` 消歧成
> `Liu, X. et al., 2023`，现编只会得到 `Liu et al., 2023`，没 Refresh 之前看着就是错的。

> ★ `docProps/custom.xml` 里的 `ZOTERO_PREF_1` 是 Zotero 认领这份文档的凭据。
> python-docx 存盘后它不一定还在，**每次写完都无脑补一遍**（幂等）。

### ★★ 2026-10-18 配一篇 65 条的稿子，踩到的六件事

| 坑 | 现象 | 绕法 |
|---|---|---|
| **CSL-JSON 的 `id` 不一定是条目 URI** | 条目 Extra 里写了 `Citation Key: Lipman:2023hef`（Better BibTeX 的习惯）时，Zotero 拿 citekey 当 `id`。从 `id` 反推 itemKey 会得到一个查不到 itemID 的假键，Refresh 命中不了 | 走 `items/top?format=json&include=csljson`，itemKey 从 `key` 字段拿。★ `include=csljson` 给的是 **JSON 字符串**，里面还是**单元素数组**，两层都要脱 |
| **题名规约把非 ASCII 删光** | `[^a-z0-9]+` 把中文题名《基于图像序列的树木枝干L系统建模方法研究》压成 `"l"`，于是「子串匹配」对任何含 l 的英文题名都成立，一条中文笔记能和正经文献撞成同分，报「★歧义 1.00/1.00」 | 留住 CJK；**规约后短于 14 字符的题名不许走子串匹配**，只许走整体相似度 |
| **刊名印成缩写** | `elsevier-harvard` 对期刊论文写 `container-title form="short"`，citeproc 去取条目的「期刊缩写」，印出 `Remote Sens. Environ.`；作者稿子里是全称。**65 条里 17 条因此对不上** | `排版配置.文献["刊名全称"]=True`，派生样式里把 `form="short"` 去掉。Zotero 的字段不动 |
| **叙述式引用出来是死文本** | 稿子里 `Yang and Liu (2026)` 的括号里只有年份，引用正则认的是 `(作者, 年)` 整个括号，匹配不上 → Word 里是一段死字，Refresh 不动它 | 用 `做排版源.py` 改写成 `Yang and Liu (Yang and Liu, 2026)`，`插引用` 看出「前面已经写了作者」就给字段加 `suppress-author`，显示回 `Yang and Liu (2026)` |
| **suppress-author 用现编的作者名去比** | 原来拿 `Z.author_string` 现编的 `Liu et al.` 和前文比，消歧过的 `Liu, C. et al.` 对不上 → 印成 `Liu, C. et al. (Liu, C. et al., 2023)` | 从**渲染形式**里切掉结尾的 `, 年` 当作者名 |
| **只在补充材料里引的条目被静默丢掉** | `插文献` 只收正文引到的，文献表从 65 条掉到 63 条，不报错 | `排版配置.文献["额外收录"]=("ref13","ref22")` |

另外：`排版配置.文献["装进Zotero"]` **以前根本没人读**（`主()` 里写死
`做无DOI样式()`），配了 True 也不装，作者一 Refresh DOI 全回来。已修。

## ★★ md ↔ docx 双向联动（作者在 Word 上改字）

### 怎么认出「这段是 md 的哪一块」

出 docx 时在**每个块起始处埋一个书签** `TTG0001`、`TTG0002`……
同步时按书签名定位。书签在 Word 里正常编辑不会掉，**整段删掉才会掉**，掉了就报出来，不猜。

### 中间表示：同步串

md 的一段和 Word 的一段要能逐字比，得先化成同一种串：

```
**粗** *斜* ^上标^ $x$ (Wang et al., 2022)
→  ⟪b⟫粗⟪/b⟫ ⟪i⟫斜⟪/i⟫ ⟪s⟫上标⟪/s⟫ ⟦m1⟧ ⟦c:ref1⟧
```

哨兵用 `⟪⟫` 不用 `**`：稿子里有真星号（`^1,\*^`），留 `**` 会撞车，写回时分不清。

### 三条铁律

1. **只联动文字，样式一律不碰。** 写回时 `w:pPr` 整个保留，
   作者调的字体、间距、缩进、分页、样式定义全不动。
2. **行内公式和引用只认 md。** Word 里改了它们，同步**报错不写**，让人回 md 改。
   理由：OMML 反推 LaTeX 不可靠，宁可报错也不许猜。
3. **冲突就停手。** 同一块被两方改成不同内容 → 报出来，**一个字都不写**。

### 快照

`_同步快照.json` 记的是**上次同步完成时**各方的样子。谁和快照不一样，谁就是改过的那一方。

* ⛔ 别手删快照，删了就分不清谁改的
* ⛔ **重跑 `出Word.py` 之后必须 `--重置快照`**，否则重建会被当成「docx 改了」

### 改动标红

```powershell
py -3.12 -X utf8 排版/出Word.py --标红对照 上一版_英文版.md
```

两版按块对齐（difflib，中间插删过段落也对得上）+ **按词** diff，
改过/新增的词标成深红 `C00000`，没动的词保持黑色。
公式、引用、图不标红（docx 里是 OMML / Zotero 字段 / 图，只能原样搬）。

## ★ 不排就报「文件已损坏」—— XML 子元素顺序

`w:pPr` / `w:rPr` / `w:tblPr` / `w:tcPr` / `w:trPr` / `w:tcBorders` / `w:tblBorders`
里子元素的顺序是 **schema 规定死的**，顺序错了 Word 开门就说「文件已损坏」。

最容易踩的一处：deepcopy 一个底版 `rPr`（含 `rFonts`、`sz`）再 `append` 一个 `w:b`，
得到 `rFonts, sz, b` —— **`b` 必须排在 `sz` 前面**。

所以保存前统一排一遍序（`排子元素序()` / `排rPr序()`，顺序表在 `出Word.py` 里）。

## 踩过的坑总表

| 坑 | 现象 | 绕法 |
|---|---|---|
| **主题字覆盖显式字体** | 正文衬线、标题全无衬线 | 先删 `*Theme` 属性再设实名，`docDefaults` 也要删 |
| pandoc `fancy_lists` | `(1) *Skeleton extraction* …` 被当成有序列表，变 List 样式还多出编号 | `--from=markdown+tex_math_dollars-fancy_lists` |
| pandoc `smart` | `Leonardo's` 的直引号变弯引号，docx 和 md 不逐字相同，同步每次误报 | 加 `-smart` |
| 单元格直接 `w:jc` | pandoc 按 md 的 `--:` 写的，压过样式里的居中 | 删 `w:pPr/w:jc` |
| 列宽按 0.5 em 估 | 表头 `LAI` 被拆成 `LA↵I` | 按字符分档估（大写 0.70 em） |
| 先缩字号 | 12 张表 5 张掉到 7–8.5 pt | **先收格内边距再缩字号** |
| 表里 OMML 偏大 | `m:r` 不吃段落样式，在 8 pt 表里按 11 pt 画 | 显式给 `m:r` 设 `w:sz` |
| 表下边框贴着下一段 | Word 的表没有「段后」 | 加到**后面那一段的段前** |
| `w:rPr` 子元素顺序 | Word 说「文件已损坏」 | 保存前排序 |
| 写段落把书签删了 | 下一轮同步 `KeyError: 'TTG0018'` | 清内容时先摘出书签，写完装回去 |
| citeproc 的蓝色超链接 | 参考文献题名蓝色带下划线 | 拆掉 `w:hyperlink` 只留 run，清 `color/u/rStyle` |
| `&amp;` 印出来 | CSL-JSON 里带 HTML 实体 | 喂 pandoc 之前脱一层实体 |
| 跨段落匹配不上 | md 是 CRLF，`"\n\n"` 对不上 | 统一在 LF 上匹配，写回转 CRLF |
| 书目字段另起空段 | 标题和第一条之间空一大截 | begin/instr/separate 塞进**第一条开头**，end 挂**最后一条末尾** |

### ★★ Word COM 的两个坑（排查花了一个多小时）

1. **`New-Object -ComObject Word.Application` 会接管已经在跑的 Word。**
   第一次导 59 MB 那份把 Word 卡住了，之后**每次自动化导出都接到那个卡住的实例上干等**，
   看着像「我的文档把 Word 搞死了」。换个干净的 Word，同一份文件 6 秒就导完。
   ⇒ 开导前先 `Get-Process WINWORD`，卡了先清干净。
2. **Word 的 COM 调用放在当前 PowerShell 进程里会莫名卡住**，
   同一个文件丢进 `Start-Job` 里 13 秒就导完。`渲染看图.ps1` 已经统一走子作业 + 超时。

### PowerShell / 编码

* `.ps1` 存 **UTF-8 带 BOM**，否则 PS 5.1 读中文报「字符串缺少终止符」
* PS 5.1 **没有 `&&`**，用 `;` 或 `if ($?) { }`
* 控制台 GBK，脚本里设 `$env:PYTHONIOENCODING='utf-8'`

## 验收（★ 不许跳）

```powershell
py -3.12 -X utf8 排版/验docx.py                      # ① 结构体检（字段 / 书签 / 主题字 / 文献条数）
powershell -ExecutionPolicy Bypass -File 排版\渲染看图.ps1   # ② 真 Word 导 PDF → PNG
py -3.12 -X utf8 排版/比文献表.py 排版/_预览/xxx.pdf   # ③ 印出来的文献 vs 稿子里写的，逐条比
py -3.12 -X utf8 排版/核DOI.py                       # ④ DOI 去 Crossref / doi.org 核实
```

★ **③ 这一步是新加的，别省。** 出 Word 不报错只说明字段拼对了，不说明印出来的
那一行和作者写的是同一条 —— 刊名缩写、条目类型（preprint 印成 `(Preprint)`）、
页码换成文章号、人名缩写多一个字母，都只有逐条比才看得见。
★ 比的时候**先小写配对，配上之后必须再按原样比一次大小写**：
Zotero 里 Bonan 2008 的刊名存成小写 `science`，压成小写和稿子一模一样，
报「逐字相同」，印出来却是小写的 `science`。

★ **Crossref 404 ≠ DOI 是编的。** CNKI（10.13287 / 10.13466）、Eurographics
（10.2312）、J-Stage（10.18960）、arXiv（10.48550）分别挂在 JaLC / DataCite 下，
Crossref 查不到。`核DOI.py` 会退到 `doi.org` 内容协商再问一次。

**「跑通」≠「对」。** 脚本不报错只证明 XML 合法。必须真渲染成图，一页页看：

```
□ 标题层级的字体字号对不对（主题字那个坑会让标题变无衬线）
□ 三线表：三条线在不在、表头加没加粗、单元格居没居中、有没有被挤到换行
□ 公式：编号右对齐、公式居中、分式和求和画对没有
□ 图：有没有变形、图注跟没跟着图
□ 参考文献：有没有 DOI（不该有的话）、是不是黑字无下划线、悬挂缩进对不对
□ 页数和词数（Word 自己数的，不是你估的）
```

> ★ **验收只认真 Word。** LibreOffice 画 OMML 很糙（`\lVert` 画成 `//`、`\mathbf` 不加粗），
> 拿它验公式会看错。想快速看版面倒是够用：
> `soffice --headless --convert-to pdf --outdir <目录> <docx>`
