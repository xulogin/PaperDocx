# 压词：只许删冗余，不许把句子并长

作者说「要到 17000 词」「改完要几方面都比之前好」时怎么干。

---

## ★★ 先建对比体检，再动刀

**词数变少太容易了 —— 删掉内容就行。** 真正要证明的是
「短了」的同时「一点东西都没少」，而且别的维度也没变差。

所以**先写 `对比版本.py`（六项），再开始改**：

| 项 | 看什么 | 判据 |
|---|---|---|
| ① **信息守恒** ★★ | 数字 / 引用 / 图表公式节引用 / 缩写，旧版有的新版还在吗 | 丢了要**逐条说得出理由** |
| ② 词数 | 总量 + 分节 | 朝目标走 |
| ③ RSE 惯例 | 该避的词别变多、该有的别掉到 0 | 不许变差 |
| ④ 可读性 | 平均句长、超长句（>45 / >60 词）、路标句 | 要降 |
| ⑤ 术语一致性 | 项目定下的那几条 | 都该是 0 |
| ⑥ 结构 | 图、表、公式、标题数 | 不许变 |

---

## ★★ 实战教训：分号并句是假精简

第一版我用分号把相邻句子并起来当「精简」，`对比版本.py` 当场判死刑：

```
超长句 >45 词    57 → 63     ⛔ 变差
平均句长        26.7 → 28.5  ⛔ 变差
主动语态 we+动词  14 → 9      ⛔ 变差（有几处被我改成了被动）
信息守恒        L1/L2/L3 → 具体节号的映射丢了三处
```

**分号并句一个词都省不了**，只是把句子拉长。全部退回重做。

原则定死：

> **只删冗余词和整句冗余，绝不把句子并长，绝不把主动改被动。**

## 能真省词的只有三种

| 做法 | 例子 | 安全吗 | 能省多少 |
|---|---|---|---|
| **删纯过渡/路标段** | 「我们分三方面报告」「下一节讲 X」 | ★ 最安全，还降路标句 | 一段 15–40 词 |
| **表格行标题去重复** | 指标名重复 11 遍 → 拆成「指标\|变体」两列 | ★ 安全，还更好读 | 一张表 20–60 词 |
| **逐词去冗** | `in which`→`where`、`among them`→`such as` | 安全但省得少 | 一处 1–3 词 |
| ~~分号并句~~ | — | ⛔ | **0，还拉长句子** |

### 什么叫「纯过渡段」

判据是：**下一段 / 下一节马上就要说，这里先报一遍**，而且不含任何事实、数字、引用。

```
✓ 可删  "We combine qualitative comparison with quantitative measurement,
         in three respects: overall morphology, size and shape, and …"
         （紧接着就是 (1) Overall morphology. (2) Size and shape. 三个黑体小标题）

✓ 可删  "How well the dimensions of these models agree with field measurements
         is examined next."   （下一节标题就是 Comparison with field inventories）

⛔ 不能删  任何带数字、带引用、带结论的句子
⛔ 不能删  交叉引用里的具体节号（读者靠它找哪一层在哪一节）
```

### 反过来：拆长句是加分项

60–93 词的长句拆成两三句，**词数基本不变但可读性真的改善**。
实测把 5 个长句拆开，>60 词的句子 12 → 7。

> ⚠ 但别见长句就拆。有一版就是这么拆成「电报文」的 —— 短句丢掉了逻辑关系。
> 只拆那种「三个并列项硬塞在一句里」的。

## 信息守恒：哪些「丢失」是可解释的

`对比版本.py` 的 ① 会报一批丢失，先别慌，这几类是正常的：

| 报的 | 实际 |
|---|---|
| 数字 `1` `2` `3` 少了几个 | 删掉的枚举标号 `(1)(2)(3)` |
| `Section 2.4.1`–`2.4.4` 四个都没了 | 被合并成了 `Sections 2.4.1–2.4.4` |
| `118` `101` 少了 | 表格里去重复的 `(n = 118)` |
| `Figure 4` 少了 | **正则把句末的 `Figure 4.` 和 `Figure 4` 当两样东西** —— 去全文 grep 一下再下结论 |

**真丢失长这样**：引用少了一条、缩写定义没了、某个实测数字不见了。
这几类在 V41→V42 那轮是 **0**（引用 96 处全在、缩写 36 处全在）。

## 一个可复用的改稿脚本骨架

把一轮的全部改动写成**声明式的清单**，而不是手动编辑文件：

```python
改("说明", "旧文本", "新文本")          # 段落内逐字替换，旧文本必须恰好出现 1 次
换块("说明", "块开头的唯一前缀", "新的整段")   # 整段重写，一段要动五六处时用
删块("说明", "块开头的唯一前缀")          # 整块删（只用于纯过渡段）
并块("说明", "前缀甲", "前缀乙", "新英", "新中")  # 相邻两块合并
```

好处：

* 每条都带**说明**，三个月后能看懂当初为什么这么改
* `旧文本必须恰好出现一次`，否则**停手不写** —— 防止改错地方
* 自动统计每条省了多少词
* 先 dry-run 看效果，确认了再 `--写`

### 两个坑

1. **跨段落的旧文本匹配不上** —— md 存的是 CRLF，`"\n\n"` 对不上。
   统一在 LF 上匹配，写回再转 CRLF。
2. **跨段落合并不能用逐字替换**：中英对照版里两个英文块中间隔着中文，
   那边根本匹配不到。合并必须在「块」这一层做。

## 改了英文表的结构，中文表必须跟

如果有中英对照版，`自检.py` 那类检查会当场报：

```
⛔ | Metric | Variant | … → 列数 英[9] 中[8]
⛔ | Species | Reference | … → 数值 英60 个 中64 个，不一致
```

这条检查是为了抓「机翻把单元格复制一份挂在最后一根 `|` 外面」才加的
（`|` 的个数恰好不变，光数 `|` 查不出来），别绕过它。
